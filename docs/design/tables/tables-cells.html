Cells and rows

What each kind of value looks like in a column, and the four rows the sheet has besides the ordinary one. A screen declares each column’s kind and gets the face, colour and alignment from that kind. It never states a size or a colour itself, which is how RecordValueKind already works for text, codes and money.

Four rows besides the ordinary one

The sheet has a group row, an expanded row, a total row and a row with a promoted action. Each is drawn below on a real screen’s data.

Group row, and a promoted action

The group row is a 40-tall surface.sunken band with the day as an eyebrow and the count beside it, the way Shift history already heads its days. It only appears where the screen already groups. Returns does, and Logs explicitly does not.

A pending return promotes Verify beside the menu, because that is the one thing anyone opens a pending return for. The button needs the same role and callable as today; without them it is not drawn, and the foot says who can verify, once.

Expanded row

A receipt’s lines fold under its row. They are indented under the item column, and each line total sits in the Total column, so the column still adds up when read straight down. The disclosure is a 48 target in its own 32 column. The fold is spatial, so it opens on a spring and can reverse from wherever it is.

The open row keeps the surface.overlay fill, and the lines sit on surface.sunken.

Total row, and a footnote

A total row is surface.sunken above the foot, with border.strong over it. It is the one place figures go mint, so the eye lands on the sum. It is drawn only where every row it sums is on screen.

A figure with a reservation carries a symbol, explained once in the foot. Here ≤ means “at most”: profit where some sale lines carry no cost. That replaces a paragraph per card.
